# gate4ai/sync

Клиент синхронизации файлов с сервером gate4.ai — трей-приложение под Mac, Windows и Linux,
чистый Go без CGO.

Становится основным каналом синхронизации: сторонний плагин Obsidian remotely-save остаётся
дополнительным вариантом, но перестаёт быть единственным. В отличие от него, этот клиент
работает как отдельный процесс — не зависит от того, запущен ли Obsidian — и синхронизирует
произвольные локальные папки, а не только один vault редактора.

Постановка задачи — issue [gate4ai/server#38](https://github.com/gate4ai/server/issues/38).
Протокол (control API поверх WebDAV, pairing) — [docs/sync-api.md](https://github.com/gate4ai/server/blob/dev/docs/sync-api.md)
в репозитории сервера, это единственный источник истины для контракта между клиентом и
сервером.

## Как это работает

1. Первый запуск создаёт иконку в трее с единственным пунктом меню — «Open settings».
2. Клик открывает в браузере локальную страницу настроек (`http://127.0.0.1:<port>/`) — у
   клиента нет собственного GUI, вся настройка через браузер.
3. На ней выбираются локальные папки для синхронизации (обычный HTML-пикер поверх
   `os.ReadDir`, без нативных диалогов) и нажимается «Connect to gate4.ai» — это открывает
   `https://gate4.ai/link?client=<id>`, где папка привязывается к vault'у аккаунта.
4. После привязки клиент сам регистрирует каждую выбранную папку на сервере, получает по
   WebDAV-credential на папку и начинает периодическую двустороннюю синхронизацию.
5. Разрешённые типы файлов, максимальный размер и период поллинга задаются в личном
   кабинете на сервере, а не в этом клиенте.

## Какой сервер используется

По умолчанию клиент говорит с продом — `gate4.ai` (cabinet) и `dav.gate4.ai` (control API +
WebDAV). Чтобы направить клиент на тестовый стенд вместо прода, задайте перед запуском:

```
GATE4AI_SYNC_HOST=test.gate4.ai go run ./cmd/gate4ai-sync
```

Значение подставляется в оба адреса (`https://<host>` для cabinet/`link`,
`https://dav.<host>` для control API/WebDAV) и **не сохраняется** в `config.json` — это
чисто ключ запуска, не постоянная настройка. Без переменной действует `gate4.ai`.

## Сборка

```
go build ./cmd/gate4ai-sync
```

Без CGO на всех трёх платформах — `CGO_ENABLED=0 GOOS={linux,windows,darwin} go build ./...`
проверяется в CI (`.github/workflows/ci.yml`).

## Структура

- `internal/config` — единственный плоский JSON-файл настроек клиента.
- `internal/webdavclient`, `internal/controlclient` — клиенты протокола (см. `docs/sync-api.md`).
- `internal/syncengine` — three-way сравнение локального/удалённого состояния и манифеста,
  last-write-wins при конфликтах.
- `internal/loop` — фоновый цикл: pairing → регистрация папок → синхронизация.
- `internal/webui` — локальный HTTP UI настроек.
- `internal/trayapp`, `internal/autostart`, `internal/browser` — трей, автозапуск, открытие
  браузера.

## Статус

Реализован полный цикл из issue #38: pairing, регистрация папок, двусторонняя
синхронизация, трей, автозапуск. Не реализовано (сознательно, см. issue): предобработка
файлов на клиенте, конфликт-копии, реакция на изменения файловой системы в реальном
времени (только поллинг).
